# Agent Note: content read of the main network's outputs (MainRead)

Status: implemented

## Problem

With the H-Net dechunk (EMA plus STE plus residual, the same in our code and the reference code), a position reads only the inner output of its own chunk. On synthetic recall, chunks at both stages start at or before a word, so at the word's first letters, where the document memory pays, every coarse output a byte reads was formed before the word began ([recall gain by boundary](../../../../lab/experiments/refuted/2026-11-03-recall-gain-by-boundary.md)). The decoder must pick the next word from a bag of the document's words in one vector, and in 24,000 steps the decoders took 4% of the memory that way ([main path recall budget](../../../../lab/experiments/successes/2026-11-02-main-path-recall-budget.md)).

## Decision

`hnet/mainread.py` adds an optional attention read to a stage (`model.stages.N.main_read.head_dim`; absent by default). Queries come from the stage's encoder output at the position. Keys and values are always the **main network's** outputs, one per main chunk, in their first d dims (the slice the innermost EMA reads), at any stage. A position may read main chunk j only if j is at or before its main index: `Stage.forward` composes the read indices inward (`compose_read_index`: position, then inner position, then main chunk) and passes the set of main chunks the position's EMA path already depends on. So the read has the EMA path's causality, and a stage's own outputs, which carry local content through their residual, are never keys. Each `StageAux` carries `main_out` and `main_idx` for the stage outside it.

The output projection starts at zero, so a stage with MainRead starts as the plain stage. The output adds to the decoder input next to the EMA read and the residual. The coarse-path probe (`Stage.ablate`) zeroes or shuffles it with the EMA read; `probes.ablated(..., part="read")` (`Stage.read_ablate`) ablates the read alone, and the trainer logs `probe/read_{zero,shuffle}_s{s}`. FLOPs (`hnet/flops.py`, keys at main resolution) and params count it. In training it compiles with dynamic shapes, like the stage glue. Tests: `tests/test_mainread.py`, and the compile-parity tests in `tests/test_gpu.py` with a read at every stage.

The read belongs at the level whose positions have seen the current word. At stage 1 the query had not: stage-0 chunks also start at the space, and the stage-1 read did not let the memory through ([decoder reads main by content](../../../../lab/experiments/refuted/2026-11-03-decoder-reads-main-by-content.md)). At stage 0 every byte has seen its word's letters so far, and there the read takes 27% to 65% of the document memory on synthetic recall in 6,000 steps (the plain layout: 4% in 24,000): [bytes read main by content](../../../../lab/experiments/successes/2026-11-03-bytes-read-main-by-content.md).

## Alternatives considered

- **Sparse content read over clustered keys (Latent Sparse Attention, arXiv 2610.42147).** The idea is the same, but its point is speed at 1M+ keys. Here a position sees at most about 460 main outputs, so dense attention costs less than one stage block and needs no clustering code.
- **At stage 0, keys from stage-1 outputs (the stage's own inner net).** That was the first design (read the inner net, whatever it is). Stage-1 outputs carry each position's local content through the residual, so a stage-0 read over them is a path across the document that skips the main network. Keys from main outputs keep the main network the only path.
- **Read from the full-width main output (512) instead of the d = 256 slice.** It gives the read more than the EMA sees, so a gain could come from the extra width and not from the content match. Rejected to keep the comparison to one change.
- **Queries from the decoder input z (EMA read plus residual).** z contains the EMA read, so the probe's shuffle would change the queries too, and the residual starts at a constant (zero-init weight). The encoder output has the position's own prefix from step 0 and does not depend on the inner path.
- **Chunks that start inside words (a router change).** It would let the plain EMA read see a prefix, but it fights what the routers learn on their own (they cut at spaces), and it changes the chunking that the rest of the design assumes.

## Consequences

- 262,656 params at d = 256 per stage with a read; FLOPs per stage-s position 4 d^2 + 4 d x mean context over the main positions, plus 4 d^2 per main position.
- The read is an architecture change to H-Net, close to the Byte Latent Transformer's cross-attention decoder when it sits at the bytes. A result with it says the chunk interface was the bottleneck. It does not say the plain H-Net would learn the memory with more steps.
- On text (reference layout, 786M bytes, 5 seeds) the read stays inert: its probe cost is under 0.004 bits per byte at every eval, and the edu bpb grade is not supported ([byte read on text](../../../../lab/experiments/refuted/2026-11-03-byte-read-on-text.md)). The read stays off by default and is not in the text ladder runs. It remains a tool for synthetic recall and for later tests where the main network holds content the outer paths lack.
- `Stage.init_weights` draws the read's weights before the inner net's, so a read arm and a plain arm with the same seed start the inner nets from different weights.
- `Stage.forward` runs one more compiled function when the read is on; the plain path is unchanged except for two aux fields.
