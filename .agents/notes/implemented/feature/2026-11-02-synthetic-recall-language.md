# Agent Note: Synthetic recall language

Status: implemented

## Problem

On text, the main network of our 2-stage H-Net comes online late or not at all, and each test of that costs hours (786M to 3.15B bytes per seed). Two causes fit the data: the main network's content is worth little on text until the outer stages have learned local statistics, or something in our stage-1 path stops the decoder from reading content that is worth a lot. Text cannot separate them: we do not know how much its long-range content is worth at a given budget.

## Decision

A synthetic byte language where a document-level memory is worth a known, large amount, with an exact oracle (`lab/spikes/2026-10-30-two-stage-hnet-smoke/hnet/synth.py`, built by `scripts/make_synth.py`, data configs `configs/data/synth_{recall,norecall}.yaml`):

```
lexicon 8,192 random words (3..8 letters)        -> spelling: a local job
recall document: 32 lexicon words, each slot uniform over them; norecall: each slot uniform over the lexicon
delimiter " " or SEP (p 1/150)                   -> documents of about 1,000 bytes
oracle: P(next byte | prefix) from word masses over a prefix trie (seen words 1/32, unseen q), exact
anchors (val, full-document context): recall 1.021 bpb, no memory 2.006, norecall 2.005
```

- The two languages share one lexicon, so the spelling job is the same and only the value of memory differs.
- The oracle sees the whole document, so it is a lower bound for a model whose window starts inside a document.
- `tests/test_synth.py` checks that the oracle sums to 1 over every next byte at every position, for both languages.
- `oracle_bits(reach=R)` keeps only the words that start in the last R bytes. It is the same posterior for a predictor that sees only those bytes, so it bounds a model whose every path reaches R bytes back. `scripts/reach_anchors.py` writes `reach_bpb` into `recall/meta.json` after it reproduces the full oracle. Tests: reach 0 equals the no-memory oracle, reach beyond the document equals the full oracle, and bpb falls as reach grows.
- First use: [hierarchy on synthetic recall](../../../../lab/experiments/refuted/2026-11-02-hierarchy-on-synthetic-recall.md).

## Alternatives considered

- **Another real modality (DNA, as in the H-Net paper).** Cheaper per byte than text only in entropy, and its long-range value is as unknown as text's. It does not separate the two causes.
- **A topic-mixture language** (each document has a hidden topic, words drawn from the topic's distribution). Its memory is a bag-of-words sum that a Mamba-2 stack can accumulate cheaply, so it gives the main network a weak edge. Recall of exact random words is a job attention does well and a small recurrent state does poorly.
- **Recall spans beyond stage 1's attention window** (so only the main network can hold the memory). Not done first: with a 4,096-byte window and stage 1's 1,024-position window (about 3,000 bytes), there is little room. The follow-ups showed that the outer Mamba-2 stacks hold the memory at any window ([main network takes recall](../../../../lab/experiments/refuted/2026-11-02-main-network-takes-recall.md)), and that stacked small windows still reach far (reach anchors above). The test that isolates the main network changes the layout, not the language ([main network sole path](../../../../lab/experiments/refuted/2026-11-02-main-network-sole-path.md)).

## Consequences

- `HNET_DATA_DIR/synth/` holds 2 x 408M bytes (train and val for each language), regenerated by `scripts/make_synth.py` (seed 0, 14 s).
- The eval's BPE bytes/token and the in-context probe still run on synthetic data; the probe's edu paragraphs make its numbers meaningless there. The coarse-path probe uses the synthetic val batches.
